## Ambiguities (NOT resolved by invention; the choice made is stated so the code-freeze check can overrule it)

- **A1 (coverage, l. 539).** "Covered origins" is undefined. Implemented: a span slot whose `meta`, `quotes`, `features` and sidecar are all sealed. P's file is checked separately
  by the 90% line, whose denominator is the 120 expected origins (`expected_origins`), not the covered ones.
- **A2 (on time, l. 228-229).** "Logged before slot k + 1's time" is read as `written_utc < grid slot time(k + 1)`; the log's and the file metadata's `spec_sha256` must both equal the pin
  (else `spec_mismatch`). A prediction file whose row count differs from `features/<k>`, or whose `features_sha256` metadata differs from the sealed features file, is `misaligned`
  (extra capture-level class, no units); the text lists only absent / late / spec_mismatch (l. 252-253, l. 163).
- **A3 (M6 design, l. 433-451).** (a) Reference slot of the 11 slot dummies is unstated: slot-of-day 0 (00:31Z) is the reference (dummies `sd1..sd11`). (b) The text does not repeat LT13's
  clause (b) (zero-variance demeaned columns removed before the rank); it is vendored with the rule and the removed columns are printed (`zero_variance_dropped`). Read literally, a
  constant `log1p_liq`, `spread_c`, `mo_d2h` or `zlog_rv` (none is in a drop group) would make the fit NaN. (c) Which rows form M6's sample is unstated: the 10k-100k tier, top decile
  (`D = 1`) and deciles 4-6 (`D = 0`) after the family exclusion. (d) Deciles 4-6 are positions `[3 nt, 6 nt)` with `nt = ceil(n/10)`; the text gives no position arithmetic. (e) `VIF_w`
  (l. 586): the "w" is not defined; an unweighted VIF of `D` on the retained demeaned controls is printed as `vif_D`.
- **A4 (signed decile, l. 429, 579; map `census_map_ch269.py:843`).** Implemented as the same C_k sorted by signed `s` descending, ties `market_id`, first `ceil(n/10)` (not filtered
  to "up calls only").
- **A5 (sports and crypto arms, l. 431, 590).** "The same reader" with the scope parameter: `sports` = the sports classifier is true; `crypto` = not sports and the crypto class is not
  `non_crypto` (unknown counts). The decile is cut within each arm's own candidate set. Only counts by tier are printed.
- **A6 (design MDE, l. 548-549) - may bind.** (a) Cluster sizes are scaled by the projection factor 21 / covered days (conservative: persistent events and days hold more units);
  unscaled sizes would give a smaller DE. (b) The two-way SE uses `DE_event + DE_day - DE_(event x day)` (the text names counts "per event, per event x UTC day, per UTC day"). (c) `n` is
  the projected labelled units. With the 0.02 within-cluster correlation and about 1,200 units per UTC day, the day-cluster DE is about 50, so the design MDE can sit above the
  declared one and the F-MDE (x 1.581) lands near the 0.5c line: on a 600-market synthetic world the design F-MDE was 2x the declared one. Whether F-MDE <= 0.5c can fail on the
  design term alone for realistic counts is for the reviewer.
- **A7 (`m_21`, l. 502-503).** Read as (units / distinct markets in the census) x 21 / covered days (7.47 in 104 captures -> about 18 in 252 in the text's own arithmetic).
- **A8 (projected labelled-eligible units, l. 554).** Read as units with class `labelled` at k + 1 (stricter than all units), projected x 21 / covered days.
- **A9 (restore, l. 530, 6).** The restore of the engine stores from the verified release is selected by the caller's `restore_from_archive.py` arguments; `lt14_restore_guard.py`
  adds only LT13's readiness and bytes-first checks and no engine-file selector.
- **A10 (lane).** The census job is written with `lane: net` as 6 item 3 says, although it makes no network request; the 800 MB refusal is an in-process RSS check, not the queue's cap.
- **A11 (family rule, l. 268-269, 565).** Applied to the gates after the cut, to the top units and to the rest-of-tier unavailable share alike; the pre-exclusion unit count is
  recorded (`n_units_before_family_exclusion`).
- **A12 (champion changes, l. 214-216, 587).** `champion/history.jsonl` lines are embedded in the seal; the census prints the line count and the champions named. "Champion changed in
  window" is not derived (the history row format carries no confirmed timestamp key); the label stays for the analysis stage.
- **A13 (confusion table, l. 581).** Computed on rows entering step 5 (after steps 2-4), by tier x engine `category` x classifier label (sports / crypto / unknown / non_crypto), because
  after the scope step the classifier axis is degenerate.
- **A14 (two-member neg-risk share, l. 134, 589).** Event size = rows of `features/<k>` with that `event_id` (>= 0); share of primary units with `ms_neg_risk = 1` and size 2.
- **A15 (tier edges, l. 270-271).** `expm1` of the float32 `ms_log_liq` can fall a hair off an exact cut ($10,000 stored as 9999.99): used as stored, as the text says.
- **A16 (per-capture statistics, l. 542).** "Covered captures, zeros included" counts a covered capture whose P file is absent / late / mismatched as 0 units, which lowers the
  median and the non-stationarity ratio on top of the 90% coverage line.
- **A17 (`SD_plan`, l. 543).** `ddof = 1` standard deviation of `mo_d2h` over the primary units, x 100 to cents.
- **A18 (`L_c`, l. 237).** `written_utc` of P's first valid log line minus `meta/<k>.finished_utc`.

## Findings

- **No exact collinearity or by-construction failure in the census lines** was found beyond A3(b) and A6. The M6 list has no identity in its rows (the 12th slot dummy is omitted, the
  stated 11); `D` is a function of `P`'s inputs (disclosed at l. 439-440) and its VIF is printed. `|mid_k - ms_mid| <= 1e-6` holds with float32 storage (each of bid, ask, mid is off by
  at most about 3e-8).
- Outside this scope, for the later stage: the placebo condition `|gbar_pl| < 0.5 x gbar` (l. 341) cannot hold when `gbar <= 0` (the expected Contradicted case), so the label
  "common direction not excluded" is set by construction there; it changes no verdict (Contradicted needs only the CI below 1.30c, l. 392).
