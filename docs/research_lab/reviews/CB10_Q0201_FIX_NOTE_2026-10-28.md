# CB10 q0201: ruling request (NOT_EXTRACTABLE, composite ids, exit codes)

Date: 2026-10-28. Status: request for a science-reviewer ruling. q0201 is NOT queued; its spec stays in `queue/drafts/`.

## What NOT_EXTRACTABLE means, and why it was unreachable
Label (from CB8 `cb8_exclusion_fix`, reused by `cb9_exclusion_fix.build_seal_plan`): a committed seal copy from which NO market id can be extracted,
i.e. `seal_ids_from_copy` is empty and its `pred_prices/` + `pred_trades/` file names give no `<pred_market_id>__<pred_event_id>` pair. Such a seal adds
nothing to the exclusion set, so disjointness against it is unverified. `cb8_books.seal_copy_ids_audited` puts every committed copy without market ids
into `skipped` (`no_market_ids`), so `used` (the only input of `build_seal_plan`) never held one. Two consequences: (a) a seal with only `pred_*` files lost
its predecessor market ids and event ids entirely; (b) a seal with nothing extractable was only a line in `seal_copies_skipped`, never labelled or counted.
On the host at q0182b: cb11_attn/pol/w_hold/wprints, cb12_say, cb13_touch, h8_geo, h8_text were `no_market_ids` (none had pred-only files, per the q0182b note).
Seals committed since may differ; this fix makes that case visible either way.

## Fix (`backend/astrolabe/research_lab/cb10_exclusion_fix.py`, active only under `run_cb10.py exclusion-keys --normalise-ids`)
Run-scoped, restored on exit. `seal_copy_ids_audited` is wrapped (before `cb9_exclusion_fix.normalised_exclusion_ids` captures it): each `no_market_ids` copy
moves from `skipped` to `used` with a sha256 pin. A pred-only copy then contributes its pred market ids and pred event ids through the unchanged mapping rule
(q0164b ruling); a copy with nothing gets `label = NOT_EXTRACTABLE` from the unchanged `build_seal_plan`. `build_seal_plan` is wrapped only to add
`n_not_extractable` and `not_extractable_seals` to counts (manifest `params.exclusion_fix.counts`, sidecar, run report). Unparseable and `not_committed` copies
stay skipped with their original reason. Unresolvable ids still refuse. NOT_EXTRACTABLE does not refuse the run: the count is the disclosure; the unverified
share of ids stays bounded by the existing 2% missing-metadata rule. Question for the reviewer: should a nonzero NOT_EXTRACTABLE count instead block D/B
(it does not today; a seal with no ids cannot overlap by id, but could overlap by event key)?
Disclosed residue: the write-once sidecar note text (from `cb9_exclusion_fix`) still reads "q0182 failed ... q0182b is the fix run", and the inherited q0182b
gap (pred event ids attached only to found markets; `n_pred_event_ids_not_in_any_key_set`) applies to q0201 too and is reported.

## Exit codes
`run_cb10.py` now maps `cb9_exit.incomplete_exit_code` onto the q0201 result: 0 only when complete or a declared stall (`exclusion_keys_complete`,
`disjointness_unverified`); 75 on a transient incomplete stop (network, 429, should_stop); 1 on a non-transient one; 4 disk budget and 2 refused unchanged.
Previously `_result` returned 0 on any incomplete stop, so the queue could have marked a partial run done and started D/B jobs. The `repeat` block is removed from
the spec (as q0182b): 75 re-queues, batches resume by position, the sidecar refuses a changed id set. `--budget-min` is refused under `--normalise-ids`.
