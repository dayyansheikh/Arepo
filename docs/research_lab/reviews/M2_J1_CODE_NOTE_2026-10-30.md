## Spec gaps (found while coding; not resolved by inventing thresholds)

1. **`cb13_label.py` is missing from the module-pin list** (coordinator's instruction): `cb17_census.is_sports_sidecar` reads its `first_series_slug`, `SPORTS_CATEGORIES` and `SPORTS_SERIES_RE`, which decide E5 sports scope. It is in `PIN_MODULES` (8 files). The doc's list (and 19's "six imported modules") must be amended before the freeze.
2. **Seven vs six modules:** section 5 lists six names in parentheses and then adds `live_tests8_base.py`; I pinned all seven named plus `cb13_label.py`.
3. **E4 vs E5 and `sidecar_missing`:** E4 needs `accepting_orders` (a sidecar field), so a market with no sidecar row would be `accepting_unknown` and E5's `sidecar_missing` would be unreachable. Implemented: open flags first (`not_open_at_k`), then a missing sidecar row is `sidecar_missing`, then `accepting_unknown` / false-flag. Needs a one-line decision.
4. **E3 `prior_unit` and E2 `already_overdue_at_k_minus_1` are unreachable by construction** (a unit's market is in the overdue-seen set; a folded k - 1 puts every overdue market there). Kept as guard classes; expected 0.
5. **`left_before_overdue_slot`:** the definition ("present and open at k - 1, `end_date_{k-1} <= start_k - 2 h`, absent or closed at k") also matches markets already overdue at k - 1 that close at k. I added "not already overdue at k - 1" (age < 2 h), matching the stated purpose ("before a first overdue capture"). Also, "open" at k - 1 is taken from the row flags (binary, not closed, active), scope from k - 1's own sidecar row. The watch set is bounded by `end_date <= start_{k-1} + 3 h`, the longest k - 1 to k gap the 30-min slot tolerance allows (a code bound, not a design threshold).
6. **`end_date_missing` "counted per capture for scope markets":** counted over all rows with an unparseable `end_date` whose sidecar row maps to the scope category, open or not.
7. **Receipt time of a committed poll line:** the doc does not name the field. I use the poll line's `finished_utc` (the commit moment, `streams/common.py`). In `receipt` mode a poll without a parseable `finished_utc` contributes nothing (never guessed); J0 reports how many committed polls carry one, and `decisions.rule_e_day_before_reader_applies` is true only if none do. If some do and some do not, the doc's rule (e) ("no parseable receipt time") does not say what to do; the code stays in `receipt` mode and J0 prints the counts.
8. **`t_d` fallback:** if neither the row's nor the sidecar's `received_utc` parses, `t_d` = the capture's manifest start (`t_d_source` recorded). The doc is silent.
9. **Window edges:** the doc says the first possible k is the first capture whose k - 1 starts at or after `REGISTERED_UTC`; implemented as `prev.start >= window_start` and `start < window_end`. Captures at or after `END_UTC` are follow-up only (no fold into the seen set, no unit). The doc does not say whether the overdue-seen set keeps folding after the window.
10. **J0 look-back:** the host keeps about 8 days, so J0 cannot use the 84-slot look-back and also leave several full days to classify. `--lookback-slots` defaults to 12 (as M1's warm-up) and the output states it; `reoverdue_seen` is then understated and early units slightly overstated. Whether rule (a) should be read on that basis is the designer's call.
11. **Test iv wording:** "deleting every follow-up file leaves every unit and status file byte-identical" conflicts with the status file carrying the follow-up file's sha256 and line count (9.2). The test runs the extractor with the recorder off and requires identical unit files and state, and status files identical except the `followup` key; it also spies that no `followup/` path is opened.
12. **State file content:** 9.2 says the state holds "the folded rule classes with their commit times". Here the rule index is rebuilt from the retained `gamma_rules` day files on every pass and the class and commit time are stored in each unit line; the state holds only the seen set, unit ids and slot ledger. If `gamma_rules` day files are retired during the window, a later pass reads less; units already written do not change. Resume re-reads the last folded capture to rebuild k - 1 (if it is already gone from the host, k is `no_previous_capture`, noted).
13. **S10 cell names beyond day 21** (a 42-day extension) are generated as `days 22-28`, ...; the doc names three cells only.
14. **S2 for market with a `hash` record whose row is outside retained files** is `rules_unresolved`; a `hash` whose sha matches a row seen in any retained file (even a later one with the same sha, same text, same class) resolves. No post-`t_d` content can enter because equal sha means equal text.
15. **Status-form printing:** `uma_other_at_k_forms` lists every non-whitelist form seen at E6 (including proposal forms), capped at 100.
