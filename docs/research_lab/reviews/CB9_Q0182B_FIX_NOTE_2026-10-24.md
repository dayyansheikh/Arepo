- Cause: same as CB8 q0164. `cb8_books.seal_copy_ids_audited` returns file-name ids of seal copies; `h7_cb4_series_SEAL.json` names its files
  `<successor market_id>__<pred_event_id>`. Gamma's `id` filter takes integers only; one bad id 422s the whole 50-id request.
- Host counts (read-only, host checkout 8c67bf29731, seal copies used: h5_cb1, h5_cb1_ladders, h6_weather, h7_cb4_era, h7_cb4_series, h8_tail):
  66,020 seal ids, **1,922 non-integer, all from h7_cb4_series** (each = `<int>__<int>`; 0 unresolvable). Extra pins: CB8 updown frame 0 ids
  (empty, vacuous), CB8-H holders 4,404 ids, 0 non-integer. Skipped (no market ids): cb11/cb12/cb13 holdout seals, h8_geo, h8_text.
- Run directory `exclusion_run9` on the host holds only `request_clock.json`: no manifest, no `exclusion_keys_partial.jsonl`. Nothing saved, nothing to
  resume; the failed-manifest aside copy is therefore a no-op here (kept in code for parity).
- Rules pinning: `cb9_common.exclusion_keys` and `load_exclusion_keys` ARE in the rules hash (`func_sources_sha256` of cb9_rules_v4.json and all kinds
  via `common_rule_funcs`); `cb8_books.seal_copy_ids_audited` and `cb6_tail.exclusion_stage/lookup_keys` are CB8-side functions. None is edited (git diff
  touches no hashed function; rules hashes unchanged).

## Equality with the CB8 q0164b ruling mapping rule
Reuses CB8's own functions: `normalise_ids` (composite -> numeric market part), `pred_pairs_of_seal` (pred_prices/pred_trades add market ids and pred
event ids), `ids_sha256`, `NOT_EXTRACTABLE` label. Same: unresolvable -> refuse (nothing dropped from the 2% denominator); write-once sidecar with pins,
per-pin counts, sha256 of the final id set, module sha256 (also CB8's module sha256); repeat run with a different set/pins refuses; failed manifest copied
aside write-once; counts in manifest `params.exclusion_fix`.

## Differences (for the reviewer)
1. Normalisation happens BEFORE `new_ids = (seal | extra) - cb8_ids`, so the composite strings are not "new"; the set sent to Gamma is the new-only set.
   Host dry run (offline, same code): 66,587 normalised seal ids (574 pred market ids new vs the seal ids), after subtracting the 324,735 pinned CB8 ids
   and adding the holders pin: **3,990 new ids, 0 non-integer**. All 1,922 pred markets are already in the CB8 key file; 12 of them have `found=0` there
   (not in Gamma), so no pred event could be attached in CB8 either. Thus CB8's keys, not re-looked-up, already carry the pred events; q0182b attaches pred
   events only to markets it looks up itself (counted: `pred_event_ids_attached_new_this_session`).
2. The sidecar `pins` are the seal copies used (name, sha256) plus the extra pins; the CB8 key file is pinned by its sha256 argument.
3. Not reproduced from CB8: the `repeat`/`--budget-min` block (3,990 ids is about 80 requests at 2 rps; the timeout and 2 retries resume by batch).
4. The host seal set (incl. h6_weather) differs from the seals in this branch; the id set is read afresh on the host and hashed into the sidecar.
5. Disclosure: CB10 q0201 reads seal copies with the same non-integer risk only if a newer seal has composite names; none known.
