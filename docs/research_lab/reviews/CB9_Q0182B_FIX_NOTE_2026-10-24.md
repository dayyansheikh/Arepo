## Differences (for the reviewer)
1. Normalisation happens BEFORE `new_ids = (seal | extra) - cb8_ids`, so composite strings are not "new". Corrected dry run: 12,640 seal ids -> 13,207
   after normalisation and adding pred market ids (574 pred markets new vs the normalised ids); after subtracting the 324,735 CB8 ids and adding the holders pin:
   **3,990 new ids, 0 non-integer** (same count as the first dry run, since h6_weather's ids were already in the CB8 keys).
   Inherited deviation of CB8 q0164b from its ruling (item 1): pred event ids are attached only when Gamma found the market. 12 predecessor markets have
   `found=0` in the CB8 keys; **`n_pred_event_ids_not_in_any_key_set` = 8** (counted against CB8's event key sets; written to the sidecar and manifest counts).
   No retroactive CB8 repair.
2. The sidecar `pins` are the seal copies used (name, sha256) plus the extra pins; the CB8 key file is pinned by its sha256 argument.
3. Not reproduced from CB8: the `repeat`/`--budget-min` block (3,990 ids is about 80 requests; timeout and 2 retries resume by batch); `--budget-min` is refused.
4. The committed seal set on the host governs (h6_weather is not committed, hence skipped); the id set is read afresh and hashed into the sidecar.
5. Disclosure before CB10 q0201 reuses the module: `NOT_EXTRACTABLE` is unreachable (`seal_copy_ids_audited` skips seals without market ids, so a seal with only `pred_*` files would be skipped entirely; none exists today).
