## Ambiguities and findings (NOT resolved by invention; for the code-freeze check and the designer)

- **A3 (material).** The control list as written is exactly collinear: K holds `spread_k` (1.7, l. 376, LT12 K_COMMON `spread_c`), 3.3 (l. 733-742) adds
  `spread_{i,k-1}` AND the own innovation `spread_k - spread_{k-1}`. None of the three is in drop groups (1)-(3) of the aliasing rule (l. 743-751), so the rule
  returns NaN ("unavailable") on every fit, the MDE gates are infinite and CH253 would be `census_dropped` by construction, not by data. The code implements the
  text exactly (`DECLARED["controls_own"]` holds `spread_km1_c`; test `test_the_declared_control_list_is_exactly_collinear_stage_A_finding_A3`); the happy-path tests
  drop `spread_km1_c` from a spec copy. A design amendment (with review) is needed before q0722 is promoted. Also, with the exact collinearity the rank decision depends on
  rounding at the pivoted-QR tolerance only if the data were rounded inconsistently (the code rounds `own_ds_c` and `spread_km1_c` at 1e-10 c; K's `spread_c` is unrounded).
- **A1.** 7.1 (l. 958-963) says vendored hash-pinned copies; LT13 imports LT12 / CH251 helpers (`live_tests12`, `live_tests12_base`, `population_map_ch251`) with their
  normalised sha256 declared and checked at seal and census (`imported_error`). No LT12 object is computed.
- **A2.** LT12's statistics cluster/demean by `event_id` x day; `lt._adapt` sets `event_id := batch_id` (the true event key stays in `ekey`).
- **A4.** Zero-variance demeaned control columns (e.g. a fee class or category constant inside a batch-day) are removed before the rank and printed
  (`zero_variance_dropped`); the text does not say (LT12 fits do the same). Without it every real fit would be NaN.
- **A5.** Batch key (l. 336-340): "stable because the registry never forgets" holds for later-created members; an EARLIER-created member joining within 120 s
  renames the batch (tested). The registry is built causally capture by capture (only captures <= k).
- **A6.** Twin (l. 892-896, 1.9): "same batch and mate rule" is read as: the k-partition of the batch and events, mates two-sided/tight/tick-unchanged/non-crypto/
  within 120 s at k + 2 and k + 3, 2 <= mates <= 30, >= 60 % of the batch complete there; the unit's own book is not required.
- **A7.** "> 30 cross-event mates": 1.4.4 (l. 343-346) says the batch holds > 30, 3.2 (l. 725) says 2 <= and <= 30 COMPLETE mates at k. Implemented 3.2
  (`gt30_units`); the 1.4.4 reading is printed beside it (`gt30_arm_units_registry_mates_reading`).
- **A8.** Completeness (l. 346, 913): members = all registry members of the batch (closed or other-category ones count as incomplete); pooled over cross-event
  batch-captures with an eligible member; "complete" = quote rules + non-crypto + receipt rule.
- **A9.** Receipt rule (l. 232-235): the batch median is over batch members with a series row (two-sided) at that capture; the unit's own receipt must also be within 120 s.
- **A10.** "Eligible complete units" (rule 21, `cbar`): non-sports ex-crypto 1.4 units with a registry row and a complete receipt, any batch/arm; decile = `np.quantile` cuts +
  `searchsorted(side="right")`; "created >= 7 days apart" inclusive.
- **A11.** Gate `VIF_w(zs_bt) <= 2.0` is computed against `cbar` and the own innovation only (l. 913); the MDE's `sqrt(max(1, VIF_w))` uses all controls (LT12 form); both printed.
- **A12.** `d_i` in the correlation gate is K's own mid change `d` (not the spread innovation).
- **A13.** Registry rows: every row with a parseable sidecar `created_at` (open or not, any category).
- **A14.** `fee_category` is verbatim (null-like -> literal `unknown`, no casefold); the crypto classifier stays the pinned strip/casefold one. The fee-class control is
  the `fee_on` dummy (unknown class -> 0). The `fee_type` x sports-slug print is taken on rows before the sports filter (after it the slug column is "no" by construction).
- **A15.** The batch-phase state-shift gate (1.8) is stage B (it needs a target); the census only needs the block-share gate.
- **A16.** `restore_from_archive.py` has no skip-existing option, so q0720 selects the full window; the seal's two-root conflict check enforces byte equality with q0710's copies.
- **A17.** Memory: the census holds all unit lines (planning ~360k rows x ~90 columns); the 750 MB lane is unmeasured (host dry run, 7.2).
